## LC 26 删除有序数组中的重复项

### 代码

```python
slow = 0
for fast in range(1, len(nums)):
    if nums[fast] != nums[slow]:
        slow += 1
        nums[slow] = nums[fast]
return slow + 1
```

### 解析

快慢指针（slow-fast pointers）范式的标准范例：fast 指针承担**扫描遍历**，slow 指针维护**已去重前缀的不变式**——循环不变式可陈述为「nums[0..slow] 恰为已扫描前缀中相异元素依序保留的结果」。每当 fast 触及与 slow 处不同的值，不变式外延扩张一步。有序性保证了重复元素必然毗连，故与单一基准比较即可判定新颖性。

- 时间复杂度：O(n)；空间复杂度：O(1)

### 心态历程

> 第一版写的嵌套循环加列表删除，看答案才知道有双指针这回事。画了两遍指针走位的示意图才彻底明白 slow 不是「跟在后面」，而是在圈定一块已经完工的区域。循环不变式这个词是今天查资料学到的，感觉给直觉找了个正式的说法。

## LC 27 移除元素

### 代码

```python
k = 0
for i in range(len(nums)):
    if nums[i] != val:
        nums[k] = nums[i]
        k += 1
return k
```

### 解析

与 LC 26 同构：k 维护「已保留元素构成的前缀」这一不变式，扫描指针 i 逐一仲裁元素的存留。差异仅在于筛选谓词由「与邻元相异」变为「与目标值不等」。两题共享同一抽象骨架——**就地压缩（in-place compaction）**：以覆盖写替代物理删除，将序列操作的时间代价约束在线性界内。

- 时间复杂度：O(n)；空间复杂度：O(1)

### 心态历程

> 做完 26 立刻做 27，有种「换皮」的感觉，但这次是有意识地去认骨架：都是前面一段维护好、后面只管扫。10 分钟内写完一次过，第一次体会到模板迁移的快感。

## LC 88 合并两个有序数组

### 代码

```python
i, j, k = m - 1, n - 1, m + n - 1
while j >= 0:
    if i >= 0 and nums1[i] > nums2[j]:
        nums1[k] = nums1[i]
        i -= 1
    else:
        nums1[k] = nums2[j]
        j -= 1
    k -= 1
```

### 解析

朴素的前向合并会因覆盖写而**摧毁尚未消费的源数据**——这是就地算法的经典陷阱。逆向放置策略（从尾部填充）利用了 nums1 尾部 n 个空闲槽位构成的**缓冲区**，使写入位置始终滞后于读取位置，从根上规避了读写冲突。三指针分别锚定两序列的有效尾端与合并序列的填充尾端，循环终止条件只需看守 nums2（nums1 残余元素本已就位）。

- 时间复杂度：O(m + n)；空间复杂度：O(1)

### 心态历程

> 正向合并写到一半发现会把 nums1 没读完的数冲掉，卡住。看提示「从后往前」的时候愣了几秒——同样三个指针，方向反过来问题就消失了。这题给我的震动比前两题大：有时候解法的差别不在代码量，在于你看序列的方向。

## LC 283 移动零

### 代码

```python
k = 0
for i in range(len(nums)):
    if nums[i] != 0:
        nums[k], nums[i] = nums[i], nums[k]
        k += 1
```

### 解析

仍是就地压缩的变奏：k 划界「非零元素已归位的前缀」，交换操作使每个非零元素平移至其最终序位。由于 k ≤ i 恒成立，交换不会干扰未扫描区域；遍历结束时 k 之后自然全零，零元素的「移除」是被动完成的。与 LC 27 的对照阅读颇有教益：同一不变式，谓词取反，交换与覆盖写可互换。

- 时间复杂度：O(n)；空间复杂度：O(1)

### 心态历程

> 这题几乎是用 27 的肌肉记忆写完的，区别在于用了交换而不是覆盖。写完后自己多想了半分钟：覆盖写法要先记原值，交换更对称。能在做完题之后还想出「为什么两种写法都行」，感觉自己开始摸到双指针的底了。

## LC 167 两数之和 II（输入有序数组）

### 代码

```python
i, j = 0, len(numbers) - 1
while i < j:
    s = numbers[i] + numbers[j]
    if s == target:
        return [i + 1, j + 1]
    if s < target:
        i += 1
    else:
        j -= 1
```

### 解析

对撞指针（opposite-end pointers）的教科书实例。有序性赋予了一种**单调性判据**：当前和偏小则左指针唯一正确的动作是右移（任何右指针左移都只会更小），偏大则对称地收缩右端。每一步比较都**确定性地排除一整行或一整列**的候选矩阵——搜索空间以线性速率单调收缩，故步数上界为 n。这是对「剪枝」最纯粹的演示：不是碰运气地跳，而是按序的性质合法地删。

- 时间复杂度：O(n)；空间复杂度：O(1)

### 心态历程

> 今天五题里最喜欢的一题。一开始想套哈希表，但注意到「有序」两个字，换了对撞指针。真正想通「为什么小了只能动左边」那一刻，画了一个 n×n 的候选矩阵，发现每步都在砍掉一行或一列——原来指针移动的本质是剪枝。今天的题整体不难，但五个题串出一条线：双指针的精髓是指针各自守护一块不变式，移动即推理。
