## LC 1 两数之和

### 代码

```python
d = {}
for i, n in enumerate(nums):
    if target - n in d:
        return [d[target - n], i]
    d[n] = i
```

### 解析

暴力枚举的所有数对构成 O(n²) 的搜索空间，其浪费在于对每个元素都重复扫描「补数是否存在于已见前缀」。哈希表将「存在性查询」压缩至均摊 O(1)，从而把双重循环坍缩为单趟遍历：边行进边登记，登记的数据结构同时充当**可检索的历史**。本质是以空间换时间，将时间维度上的重复劳动迁移为空间维度上的索引冗余。

- 时间复杂度：O(n)；空间复杂度：O(n)

### 心态历程

> 传说中的第一题。暴力双重循环先写出来 AC 了，但心里知道这是作弊。哈希解法看一遍就懂，但「先查后登记」的顺序我一开始写反了——先登记再查会把同一个元素匹配给自己。一个小顺序问题，暴露的是对「历史」这个词理解得还不够细。

## LC 209 长度最小的子数组

### 代码

```python
left = 0
s = 0
ans = float('inf')
for right in range(len(nums)):
    s += nums[right]
    while s >= target:
        ans = min(ans, right - left + 1)
        s -= nums[left]
        left += 1
return 0 if ans == float('inf') else ans
```

### 解析

滑动窗口（sliding window）范式的入门正典。窗口 [left, right] 是一个**单调演化的区间**：right 负责扩张以纳入候选，left 在满足约束后负责收缩以逼近极小。关键的单侧单调性论证——由于数组元素均为正整数，窗口和关于 right 单调不减、关于 left 单调不增，故每个 left 位置对应的最优 right 单调右移，双指针全程仅做 O(n) 次位移。内层 while 看似嵌套，实则摊还后仍是线性：左指针的总位移不超过 n。这是**摊还分析（amortized analysis）**最直观的现场。

- 时间复杂度：O(n)；空间复杂度：O(1)

### 心态历程

> 第一版写的暴力枚举所有子数组，O(n²) 过了小数据但被自己鄙视了。滑窗解法第一眼看「双重循环怎么能是 O(n)」非常反直觉，后来在纸上模拟 left 指针的总移动次数才服气——内层循环的总代价被左指针的单调性封顶了。第一次真切体会到摊还这个词不是在唬人。

## LC 206 反转链表

### 代码

```python
prev = None
cur = head
while cur:
    nxt = cur.next
    cur.next = prev
    prev = cur
    cur = nxt
return prev
```

### 解析

链表操作的核心难点在于**引用的重接序**：一旦改写 cur.next，原有的后继引用即告湮灭，故必须先用 nxt 将其**驻留（pin）**于临时变量。三指针 prev / cur / nxt 构成一条传送带：每次迭代翻转一条边的方向，prev 维护「已完成反转的前缀链」，循环结束时 prev 恰为新表头。此过程可归纳证明：第 k 次迭代后，前 k 条边均已反向且链表连通性未损。

- 时间复杂度：O(n)；空间复杂度：O(1)

### 心态历程

> 链表第一题，写完发现死循环——忘了先把 cur.next 存下来就改了指针，后面全丢了。重新画图：三个指针每次挪一格，箭头翻一个。想通之后觉得链表题的本质就是「改线之前先把线头抓住」。这个教训估计会记很久，因为是亲手踩出来的。

## LC 21 合并两个有序链表

### 代码

```python
dummy = ListNode()
p = dummy
while l1 and l2:
    if l1.val <= l2.val:
        p.next = l1
        l1 = l1.next
    else:
        p.next = l2
        l2 = l2.next
    p = p.next
p.next = l1 if l1 else l2
return dummy.next
```

### 解析

归并排序之 merge 子程序在链表载体上的投影：双指针各锚定一条有序序列的头部，逐次摘取较小者挂接至结果链——摘取的正确性由序列的有序性保证（未摘部分无更小者）。**哑节点（dummy node）**是链表工程的重要技法：它消除了「头节点特殊化」的分支，使首个挂接与后续挂接共享同一代码路径，将边界条件的复杂度折叠进常数空间的代价里。残链的整体挂接则利用了有序性的传递——剩余部分已天然有序且全体不小于已合并部分。

- 时间复杂度：O(m + n)；空间复杂度：O(1)

### 心态历程

> 没有 dummy 节点的版本写了四个分支来处理表头，丑得自己都看不下去。引入 dummy 之后代码一下瘦了一圈。今天最大的收获不是这道题本身，而是 dummy 这个模式：给边界一个「假起点」，让所有位置变得平凡。这和我前两天读 MML 的感受有点像——好的抽象都是把特例消解成通例。
