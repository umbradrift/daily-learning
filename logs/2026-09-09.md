## LC 205 同构字符串（Isomorphic Strings）

### 手稿代码

```python
d1 = {}
d2 = {}
if len(s) != len(t):
    return False

a = 1
for ch in s:
    if ch in d1:
        d1[ch].append(a)
    else:
        d1[ch] = [a]
    a += 1

a = 1
for ch in t:
    if ch in d2:
        d2[ch].append(a)
    else:
        d2[ch] = [a]
    a += 1

s1 = set()
s2 = set()
for ch in d1:
    s1.add(tuple(d1[ch]))   # 注：原稿直接 add(list)，list 不可哈希，需转为 tuple
for ch in d2:
    s2.add(tuple(d2[ch]))

if s1 == s2:
    return True
return False
```

### 解析

同构判定问题的本质，是对两个符号串施行**位置不变式（positional invariant）的等价类划分**。若两字符串之间存在保序的双射字符替换映射，则各字符在其所属串内的**出现位置多重集合之划分结构**必然同构。手稿采用的策略是：以字符为键、以其出现位置的序列为值，构建**索引化位置表（inverted positional index）**，继而将两边的划分结果提升为集合进行**外延相等性（extensional equality）**比较——一旦两集合相等，即证明两串在同一等价关系下不可区分，同构成立。

该方法绕开了显式构造字符映射函数的常规路径，转而利用「划分即不变量」这一结构性质，将映射存在性的判定归约为集合等势问题，属于对**商结构（quotient structure）**的典型运用。

- 时间复杂度：O(n)；空间复杂度：O(n)

### 心态历程

> 起初试图直接维护一张字符到字符的映射表，写到一半意识到还要处理反向映射的冲突检测，逻辑迅速变得粘稠。卡了约十分钟后换了个角度：与其验证映射本身，不如验证映射所诱导的结构——把每个字符出现的位置记下来比较分布模式，顿觉清爽。提交前被 list 不可哈希的问题绊了一下，转 tuple 后通过。体会到一件事：当正面构造受阻时，寻找不变量往往比模拟过程更有穿透力。

## LC 349 两个数组的交集（Intersection of Two Arrays）

### 手稿代码

```python
s1 = set(nums1)
s2 = set(nums2)
s3 = set()
s4 = s1 if len(s1) < len(s2) else s2
s5 = s1 if s4 == s2 else s2

for n in s4:
    if n in s5:
        s3.add(n)

return list(s3)
```

### 解析

本题要求的是两集合**交运算（set intersection）**的结果，且元素唯一。手稿的核心优化意识值得记录：通过**基数比较（cardinality comparison）**选取势较小的集合作为迭代域、势较大者作为查询域，从而将成员测试（membership test）的调用次数压缩至 min(|s1|, |s2|)。由于哈希集合的成员测试在均摊意义下为 O(1)，整个归约过程保持了线性渐近界。这是一种朴素的**计算量不对称化**思想——让遍历成本依附于较小的输入分量。

- 时间复杂度：O(m + n)；空间复杂度：O(m + n)

### 心态历程

> 这题几乎是一眼看到 set 就写完了，但写完之后多看了一眼，觉得遍历哪个集合其实是个可以计较的细节，于是补了个选小集合遍历的判断。虽然是微不足道的常数优化，但「多问一句还能不能更省」的习惯想保持下去。

## LC 350 两个数组的交集 II（Intersection of Two Arrays II）

### 手稿代码

```python
nums = []
d1 = {}
d2 = {}

for n in nums1:
    d1[n] = d1.get(n, 0) + 1
for n in nums2:
    d2[n] = d2.get(n, 0) + 1

for n in d1:
    if n in d2:
        if d1[n] > d2[n]:
            for _ in range(d2[n]):
                nums.append(n)
        else:
            for _ in range(d1[n]):
                nums.append(n)

return nums
```

### 解析

与 349 的根本分野在于：本题的论域从**集合（set）升格为多重集（multiset）**，元素的重数（multiplicity）成为不可约去的信息载体。手稿以两个字典实现**计数测度（counting measure）**的构建，再对键的交集逐一枚举，以 min(d1[n], d2[n]) 作为该元素在交集中的**重数下确界**——这正是多重集交运算的格论定义：两测度逐点取极小（pointwise infimum）。输出序列即为该测度的**支撑展开**。

- 时间复杂度：O(m + n)；空间复杂度：O(min(m, n))

### 心态历程

> 做完 349 顺手点开 350，第一反应是「这不一样吗」，细看才发现重复元素要按次数保留，set 的抽象瞬间失效。从「存在与否」到「存在几次」，信息维度上了一个台阶，数据结构也得从集合换成计数器。这题让我直观感受到：问题定义的微小松动，会迫使整套表征方式迁移。

## LC 49 字母异位词分组（Group Anagrams）

### 手稿代码

```python
d = {}
for s in strs:
    n = [0] * 26
    for ch in s:
        n[ord(ch) - 97] += 1

    a = 0
    t = []
    for nn in n:
        if nn != 0:
            t.append(chr(a + 97))
            t.append(nn)
        a += 1

    tt = tuple(t)
    if tt in d:
        d[tt].append(s)
    else:
        d[tt] = [s]

l = []
for dd in d:
    l.append(d[dd])
return l
```

### 解析

异位词关系是定义在字符串集合上的**等价关系**：两串等价当且仅当其在字母表上的**计数向量（counting vector）**逐分量相等。手稿的构造颇具匠心——以长度 26 的定长数组承载计数向量（等价于一个从字母表到自然数的**有限支撑映射**），再将其稀疏化编码为「(字符, 重数) 交错序列」的 tuple 作为哈希键。该键实质上是等价类的**正则代表元（canonical representative）**：凡落入同一等价类的字符串必生成同一代表元，于是分组问题被归约为以代表元为键的桶式聚集。

值得强调的是，该方案以 O(Σ) 的键构造代价（Σ 为字母表基数，此处为常数 26）规避了排序方案的 O(k log k)，在字母表有界的条件下实现了渐近意义上的占优。

- 时间复杂度：O(n · k)（n 为字符串数，k 为平均长度）；空间复杂度：O(n · k)

### 心态历程

> 第一反应是对每个字符串排序后拿排序结果当 key，隐约觉得排序有点浪费，就盯着「异位词到底共享什么」想了一会儿，想到字母计数才是本质特征。手写 key 的拼接过程比较琐碎，中途一度担心 tuple 里字符和数字混在一起会不会撞键，推了两个例子确认字符和计数交错排列不会歧义后才放心提交。这题的收获是：哈希题的胜负手往往不在哈希本身，而在你选择的「代表元」是否恰好刻画了等价关系。

## 今日小结

四道题同属哈希表范式，但恰成一组递进的抽象阶梯：

1. **LC 349**：纯粹的集合交，存在性语义；
2. **LC 350**：引入重数，从集合升格为多重集，计数测度的逐点下确界；
3. **LC 205**：从值域问题转向结构问题，以位置划分的等价类作不变量；
4. **LC 49**：显式构造等价类的正则代表元，实现归约式分组。

核心一以贯之：**哈希表的威力不在于查表，而在于把「按某种等价关系不可区分」的对象坍缩到同一个键上。**
